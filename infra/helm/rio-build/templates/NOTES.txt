{{- if .Values.mountd.enabled }}

── castore store via rio-mountd (ADR-022) ─────────────────────────────
Builder/fetcher pods mount their input closure through the castore-FUSE.
The per-node rio-mountd DaemonSet opens /dev/fuse and hands the fd to
the executor over /run/rio-mountd/rio-mountd.sock — executor pods never
open the device node and request no device plugin / extended resource.
/dev/kvm is still injected by containerd's `base_runtime_spec` (NixOS
AMI: nix/base-runtime-spec.nix); kvm pods route to .metal via
per-intent nodeAffinity.

Prerequisites:
  • rio-mountd DaemonSet Running on every builder/fetcher node.
  • Node provides /var/rio/{castore,cache,chunks,staging} (NixOS AMI
    tmpfiles + the rio-kubelet-mount prjquota bind).

Verify on a builder/fetcher node:
  kubectl -n {{ .Values.namespaces.builders.name }} get ds rio-mountd
{{- end }}

── Seccomp Localhost profile (node-baked, ADR-021) ────────────────────
Profiles are baked into the node image and copied to
/var/lib/kubelet/seccomp/operator/ by systemd-tmpfiles BEFORE kubelet
starts (nix/nixos-node/hardening.nix on EKS; fixtures/k3s-full.nix in
VM tests). Builder pods use seccompProfile: Localhost (RuntimeDefault +
pivot_root − ptrace/bpf/setns/process_vm_*).

Verify on a builder node:
  kubectl debug node/$(kubectl get node -l rio.build/node-role=builder -o name | head -1 | cut -d/ -f2) -it --image=busybox -- ls -l /host/var/lib/kubelet/seccomp/operator/

Profile updates: change nix/nixos-node/seccomp/rio-*.json → rebuild AMI
(`cargo xtask k8s -p eks up --ami`) → Karpenter Drift rolls nodes on the
new amiSelectorTerms tag. See docs/spec/system/security.typ
r[builder.seccomp.localhost-profile].

{{- if .Values.poolDefaults.privileged }}

── privileged:true escape hatch ───────────────────────────────────────
WARNING: poolDefaults.privileged=true is active. This disables seccomp
entirely and is UNACCEPTABLE for multi-tenant deployments (ADR-012).
It is intended for clusters that cannot deliver /dev/kvm via containerd
`base_runtime_spec`, lack the node-baked Localhost seccomp profile, or
lack idmap-mount support for hostUsers:false. Production on EKS/GKE
should use privileged:false (the chart default).
{{- end }}

── Substitution via materialization jobs ──────────────────────────────
Substitution routes through store-owned materialization jobs
(substitution-replacement design §8): the scheduler creates job rows
for upstream-substitutable derivations; store replicas claim and
execute them through the ExecutorService pull protocol, presenting
the store-service credential. The executor spawns iff
store.materialization.schedulerAddr is set (PD-D2).

Rollback below the cutover is binary-version rollback (deploy the
previous image) — the coexistence values flip is gone.
